# Firebase-backed Antty MCP OAuth

The user selected Firebase login plus an Antty-owned MCP authorization interface and explicitly requested implementation. Auth0 signup/configuration is stopped. Existing Firebase UIDs remain the account authority; no identity migration, new provider account, live credential, deployment or real-data mutation is authorized by this code change.

## Approaches and decision

Firebase ID tokens alone authenticate the existing application but do not implement ChatGPT's authorization-code/S256/resource-indicator flow. A managed OAuth provider was considered and rejected by the user. Implement a narrow first-party OAuth authorization server using existing Firebase authentication and Firestore transactions, reusing existing scoped MCP CRUD and account checks. The installed MCP SDK supplies protocol helpers, but its Express router does not supply durable grants or Firebase consent; the existing serverless HTTP pattern is retained. No general-purpose OAuth provider, open DCR, CIMD fetching, password service or refresh-token service is introduced.

## Protocol and boundaries

Fixed operator-approved public clients, exact HTTPS redirect URIs, `token_endpoint_auth_method=none`, authorization code only and mandatory PKCE S256. Publish RFC8414 authorization-server metadata and RFC9728 protected-resource metadata. The resource is exactly `{ANTTY_APP_ORIGIN}/api/mcp`. Require matching resource in authorize and token requests. A public client ID is configuration, not a secret. No new signing/encryption credential is needed: high-entropy opaque codes/access tokens are hashed before storage. Do not disclose Firebase ID/refresh tokens to ChatGPT.

GET authorization validates all parameters before any external redirect, creates a five-minute browser-bound request, and opens a dedicated consent page. Firebase authentication and recent reauthentication precede POST consent; display exact client, account, scopes and seven-day maximum grant. Login never implies consent. Cancel produces access_denied only to a validated redirect. Approved codes expire after 60 seconds. Code exchange verifies client, redirect, resource and S256 and transactionally consumes the code once while creating the one-hour token. No refresh token; reauthorization requires explicit consent again. Browser management lists/revokes only the current owner's grants. A revocation epoch prevents an outstanding consent request from restoring a revoked grant. Code exchange and verification check active grant/owner epoch/account state; failed exchanges do not burn valid codes. Revoking a grant prevents later exchange and subsequent tool requests. Already executing tool calls cannot be recalled.

The server configuration scope ceiling defaults to maps:read. All six existing maps/boards/calendar read/write scopes may be configured later, but require separate activation/consent; Calendar additionally requires its existing distinct AI Google grant and never borrows human credentials. The consent binds the current verified UID, not an email or caller-supplied owner. Fixed client callbacks and no remote client metadata avoid SSRF/open-redirect registration hazards. All OAuth state/code/token/grant collections remain Admin-only and browser SDK denied. No TTL or automatic paid cleanup is enabled. Logical expiry is mandatory; expired rows require a separately reviewed bounded manual cleanup before a long-running deployment.

## Verification and limits

Unit tests cover configuration, malformed/duplicate parameters, PKCE, exact redirect/client/resource, scopes, expiry, browser/owner binding, recent Firebase proof, cancellation, revocation and replay/concurrency. HTTP tests cover discovery, no-store/no-referrer/cookies, bounded form bodies, method/origin enforcement, OAuth errors and no invalid redirect. Emulator tests verify actual Firestore transaction races and browser-rule denial. A real MCP SDK client completes local OAuth and reads synthetic maps, then fails after revoke; existing isolated CRUD tests remain. UI tests cover explicit consent, failure/retry, duplicate submission, account change and redirect validation. Type/lint/build and independent security review precede the draft update. Hosted ChatGPT acceptance remains pending approved deployment, exact real callback/client configuration, approved test identity and actual end-to-end connection.
