## Architecture implemented in this draft

1. The person opens Antty's Agent access panel and explicitly confirms the current Firebase account, read-only mind-map scope and seven-day binding expiry.
2. The existing Google/Firebase user reauthenticates. The backend verifies the Firebase ID token with revocation checks and accepts its original `auth_time` only if at most five minutes old. Refreshing an ID token is insufficient.
3. Antty creates a five-minute server-only attempt, random state/nonce/verifier and a hashed browser secret. The browser gets a Secure, HttpOnly, SameSite=Lax `__Host-` cookie. Only the hashed state indexes Firestore; no Firebase UID is accepted from the browser. The creation transaction captures a random owner revocation epoch from server-only `mcpOAuthLinkOwners/{uid}`.
4. Auth0 Universal Login authenticates the identity the person chooses. The separate public linking application requests only `openid`, with S256 PKCE, `prompt=login` and `max_age=0`. It requests neither MCP API scopes nor offline access. The server holds the PKCE verifier; no linking client secret is needed.
5. The fixed callback requires the exact Auth0 `iss`, state and browser proof. A Firestore transaction consumes the attempt once before token exchange. The bounded, five-second, no-redirect token exchange verifies the ID token's signature, exact issuer/client audience, nonce and recent `auth_time`. A provider failure consumes the attempt; start over explicitly instead of retrying an uncertain exchange.
6. The backend rechecks Firebase account revocation and writes the exact issuer/subject → Firebase UID binding transactionally, requiring the owner epoch to still match the attempt. It refuses assignment to another UID, including for an expired/revoked subject. A same-owner explicit relink replaces the old binding with only `maps:read`, the one configured MCP client, a fresh token cutoff and seven-day expiry. Email and user-editable metadata never establish ownership. Provider tokens are discarded.
7. ChatGPT separately authorizes its **different** predefined OAuth client for `maps:read` against `https://anttykanban.vercel.app/api/mcp`. Every MCP request checks the binding and Firebase account; the existing verifier intersects token and binding scopes. The linking ID token cannot authenticate MCP.
8. The person can revoke a binding in Antty immediately. The same transaction rotates the owner epoch, canceling **all unfinished linking attempts for that Firebase owner**, including callbacks paused at the provider. Other already-active bindings are unchanged; a canceled link needs fresh explicit consent. Binding management uses owner-filtered cursor pages so accumulated subjects cannot hide revocation controls. This does not remove Auth0/ChatGPT connection records or revoke independent PATs. Disable MCP OAuth to stop all OAuth access; disabling only the link-creation flag does not revoke existing bindings. No background renewal or refresh token is implemented/requested by the linking flow.

The current setup panel intentionally cannot approve map writes, board access or Calendar access. Existing MCP CRUD code remains available for separately authorized clients/scopes and isolated tests. Future scope expansion needs a reviewed consent UI and explicit approval. A seven-day binding does not extend a one-hour access token: without offline access, reconnect/reauthorize when ChatGPT needs a new token.

## Acceptance after approved deployment

Check provider discovery advertises S256 and the actual token authentication method; the exact resource produces an RFC 9068 token and stable subject. Check link consent/cancel, duplicate callbacks, same-owner relink, collision, expiry and Firebase revocation against isolated identities. In the real hosted ChatGPT connection, require tools to appear, call `mindmaps_list` then `mindmaps_get` on the known synthetic map, confirm write/board/calendar tools are absent/denied, revoke locally and verify the next request fails. Record only redacted outcomes. No real provider or hosted-client acceptance has occurred yet.

Keep the linking application first-party for OIDC. Require user consent for the MCP API even if its predefined client is configured first-party; if configured third-party, approve only its explicit `maps:read` API client grant. Verify the actual tenant supports the chosen settings rather than using a broad management credential. [Auth0 consent controls](https://auth0.com/docs/get-started/applications/third-party-applications/user-consent-and-third-party-applications).

OpenAI documents predefined clients, discovery, resource binding and S256 requirements: [official authentication guide](https://developers.openai.com/plugins/build/auth). Auth0 documents the required tenant toggles: [resource compatibility](https://auth0.com/ai/docs/mcp/guides/resource-param-compatibility-profile).

## API costs relevant to this project

Managed OAuth Free quotas above are separate from Firebase/Vercel usage and any ChatGPT subscription. Existing hosting/database operations can consume their own allowances; no guarantee of an all-inclusive zero bill is made. Firestore TTL deletion specifically requires billing and has no free usage; a free Auth0 tenant does not make it free. [Firestore pricing](https://firebase.google.com/docs/firestore/pricing).

Google's current Calendar API page says standard use has no additional charge and documents, for new-quota projects, 10,000 requests/minute/project, 600/minute/user/project and a 1,000,000 requests/day/project billing threshold. It also announces later-2026 over-threshold billing with advance notice; older qualifying projects retain previously set quotas. Check the actual Google Cloud project quota and current billing announcement before activation rather than promising unlimited free calls. [Google Calendar usage limits and pricing](https://developers.google.com/workspace/calendar/api/guides/quota).

Restricted-test preparation, actual signup/terms gates, precise identity/credential inventory and staging/WIF limits are documented in [mcp-restricted-test-setup.md](mcp-restricted-test-setup.md). No signup or deployment has occurred.
