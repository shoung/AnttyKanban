# Managed MCP OAuth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add a fail-closed managed-OAuth resource-server path to the existing Antty MCP endpoint.

**Architecture:** A strict configuration layer pins the issuer, resource and JWKS. JOSE validates tokens; a read-only binding repository maps exact issuer/subject pairs to a verified Firebase UID and reduces granted scopes. The existing MCP transport and data layer are reused.

**Tech Stack:** TypeScript, existing `jose` and official MCP SDK, Firebase Admin, Node test runner.

**Spec:** `docs/superpowers/specs/2026-11-04-mcp-oauth-design.md`

## Global Constraints

- OAuth is disabled by default; no external credentials, services, bindings or deployment are changed.
- No email-based identity mapping, token passthrough, UID input or token-controlled fetch URL.
- Runtime relative imports use `.js` for Vercel native ESM compatibility.
- No binding write API exists until a separately reviewed, dual-proof linking workflow is approved.

## Review Focus

- A legitimate token for a different audience, client or subject must never open another Firebase workspace.
- A provider ID token must never be accepted as an MCP access token.
- Disabling OAuth or a binding must not silently fall back to a weaker credential interpretation.
- Scope reduction/revocation must take effect on the next request, even when JWKS is cached.
- Discovery failures and token errors must not leak tokens, account identities or provider internals.

## Verification and release boundary

The independent security review found no Critical or Important findings. The one Minor finding about storage outages returning 401 was fixed with a red/green regression test and independently rechecked. Local verification passed: 96 unit tests (including 16 OAuth and native emitted-handler coverage), 23 UI tests, 5 emulator security tests, typecheck, lint and build. Emulator tests used the existing /tmp cache and writable config directory. Draft publication remains the final step.

The managed-provider setup, persistent access, verified dual-proof identity-linking workflow, deployment, and live ChatGPT connection are intentionally outside this foundation and remain explicit release gates. See `docs/mcp-oauth.md`.
